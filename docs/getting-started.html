    Build the app

    JEVision is built from its source code. You need:

    • a Mac with macOS 26 or later (Apple silicon or Intel);
    • Xcode 26 or later;
    • Rust 1.85 or later, installed with rustup.

    Open Terminal and run:

    git clone https://github.com/dev-pikapik/JEVision.git
cd JEVision
apps/macos/scripts/build.sh
open apps/macos/build/JEVision.app

    build.sh builds the Rust core for both Mac architectures, then the app and the jevision command-line tool, into apps/macos/build/JEVision.app. Two settings change how it builds:

    • ARCHS=arm64 builds the app and the tool for one architecture only, which is faster: ARCHS=arm64 apps/macos/scripts/build.sh. The core is still built for both.
    • SIGN_IDENTITY signs the app with your own certificate instead of an ad-hoc signature.

    Move JEVision.app to your Applications folder if you like; the app works from anywhere.

    Allow permissions

    JEVision needs two permissions from macOS, set in System Settings → Privacy & Security. The app explains each one before it asks.

    Screen & System Audio Recording
    To take screenshots of the app under test: to find what to click, to wait for screens and to compare them with reference images.
    Accessibility (Device Control and Data Access from macOS 27)
    To click, type and press keys for you; to read the names of buttons and fields while recording, so blocks get readable names; and to notice your own mouse and keyboard, so a run pauses when you take over.

    Settings → Permissions in JEVision shows what is allowed and opens the right page of System Settings. If something doesn't work, see Permissions in the FAQ.

    Your first test

    1. Open a project. Choose Open Project… (⌘O) and pick a folder. A project is just a folder; the tests are the *.flow.json files in it. One folder per application you test works well.
    2. Create a test. Choose New Test… (⌘N), give it a name and choose the application to test.
    3. Record. Click Record (⇧⌘R) and use the app as you normally would. Every click, drag and scroll, every piece of typed text and every key combination becomes a block, with a picture of what you clicked. Drag a frame over part of the window to add a check. Passwords you type become secrets kept in the Keychain, never in the test file. Press Esc twice or click Done to stop; the steps appear on the canvas.
    4. Run. Choose Run (⌘R). The app under test comes to the front and JEVision repeats your steps. A small panel shows progress without getting in the way of the clicks. Move the mouse to pause; press Esc twice to stop the run from any app.
    5. Read the report. When the run ends, open its report to see every step with screenshots. If a step failed, the report starts with the reason. See Run video and reports.

    The first run of a check saves the picture. When a check block has no reference image yet, its first run saves the screen as that image and the report marks the step “New reference saved”. Later runs compare with it. See Checks and references.

    A test has to look to pass. A test with no check block and no wait for a picture can't notice a wrong result, so a run that ends without errors shows Nothing Checked instead of Passed, and the editor offers Add Check.

    Try the example test

    The quickest way: on the app's first screen, click Run the Demo Test. JEVision asks for the two permissions if they are missing, puts the test in the open project, or in the My Tests project (Documents/JEVision/My Tests/Demo) when none is open, and runs it. The same test is in the repository:

    The repository has a test that works on any Mac: examples/textedit. It opens a copy of note.txt in TextEdit, adds a line at the end, checks how the window looks and quits TextEdit.

    1. Choose Open Project… and pick the examples/textedit folder of your clone.
    2. Select Add a line to a note and run it.
    3. The first run saves refs/note.png, the picture the check compares with. Run it again: now the check compares the window with that picture.

    The original note.txt is never changed: an openFile block always opens a fresh copy.

    jevision.notifications.jsonOptional. Notifications to Slack, Telegram or email.Yes
    .jevision/Runs with their screenshots, videos and reports, and the history of scheduled runs.No

    After the first run in a project that uses git, JEVision offers to add .jevision/ to the project's .gitignore: screenshots and videos are results, not something to commit.

    The full description of every file is in File formats.

    Boards

    A board is a large canvas where you see your tests at a glance and lay them out your way. Boards are listed under Boards in the sidebar; click one to open it.

    All Tests appears by itself once the project has a test. It holds a card for every test, in a frame for each folder. New tests join it and deleted tests leave it on their own. Each card shows how the test last ran and when, and marks tests that are flaky or in quarantine (see Retries, flaky tests and quarantine). A frame sums up its tests, for example “3 of 5 passed, 1 failed”. Dashed arrows lead to the tests a test runs; solid ones to the tests it needs to pass first. The app draws these arrows itself.

    To make a board of your own, click + next to Boards and type a name. Right-click an empty spot on a board to add:

    • Add Test…: a card for a test that isn't on the board yet;
    • Add Note: a note, written in Markdown; double-clicking an empty spot adds one too;
    • Add Frame: a frame with a title; whatever lies inside it moves with it, and Fold shrinks it to its title;
    • Add Link…: a web address;
    • Add Image…: pictures from your Mac; you can also drag pictures onto the board or paste them;
    • Add Link to Board: a card that opens another board, or a new one.

    The Command Palette (⌘K) has the same commands, such as Add Note to Board and New Board.

    Drag an item to move it. Select an item and drag its corner to resize it, or drag the dot beside it onto another item to draw an arrow. Double-click an item to open it: a test opens in the editor, a link in your browser. Right-click an item for more, such as Run, Show Blocks (the test's steps inside its card), Color and Remove from Board. Run All at the top runs every test on the board. Scroll to move around; pinch, or scroll while holding ⌘, to zoom. Moved items snap to a grid; Snap to Grid at the top turns that off. ⌘Z undoes a change.

    With an item selected, the keyboard works too: arrow keys pick the next item, Return opens it, R runs it, B shows or hides its blocks, C starts an arrow (then click where it goes), Delete removes it from the board.

    Right-click a board in the sidebar to Rename… it or Move to Trash. Links to a renamed board follow it. All Tests can be renamed but not deleted, and its tests can't be removed from it.

    Each board is a file in the project's boards folder, such as boards/All Tests.canvas, and pictures are copied into boards/images. Commit them along with your tests. The files use the open JSON Canvas format, so Obsidian can open them too.

    Install the command-line tool

    The jevision command comes inside the app. Choose JEVision → Install Command Line Tool… and click Install…. macOS asks for an administrator's password and links the tool into /usr/local/bin. Without a password, click Install Just for Me to link it into ~/.local/bin instead. The window shows whether the tool is installed and which version. See Command line.
