    Virtual machines

    Run your tests in a macOS virtual machine: a whole Mac inside a window on your Mac. Tests take over the virtual screen, mouse and keyboard, and yours stay free.

    Why use a virtual machine

    A test moves the real mouse and types on the real keyboard, so while it runs on your Mac you can't use your Mac. In a virtual machine it's different:

    • You keep working. The test clicks and types inside the virtual machine's window, not on your desktop.
    • Every run starts clean. Prepare a virtual machine once, then start each run from a fresh copy of it: no leftover settings, files or sign-ins from the last run.
    • Two runs at once. Two virtual machines can run tests at the same time.

    JEVision doesn't make the virtual machine for you. You set it up once with a free tool, such as Tart or UTM, and JEVision works inside it like on any Mac. Other tools built on Apple's virtualization, such as Parallels Desktop or VirtualBuddy, work the same way.

    What you need

    • A Mac with Apple silicon (M1 or later) to run the virtual machine. Macs with Intel processors can't run macOS virtual machines with these tools.
    • macOS 26 or later inside the virtual machine, like on any Mac that runs JEVision. Your own Mac needs a macOS version that can run it: the newest one is safest.
    • Memory and disk: give the virtual machine at least 8 GB of memory and 4 processor cores. macOS with your app and Xcode tools takes 60–100 GB of disk.

    Make a virtual machine with Tart

    Tart is a free command-line tool. It downloads ready-made macOS virtual machines, so you don't install macOS yourself. In Terminal on your Mac:

    1. Install Tart with Homebrew: 
      brew install cirruslabs/cli/tart
    2. Download a macOS virtual machine and name it jevision. This downloads about 25 GB once: 
      tart clone ghcr.io/cirruslabs/macos-tahoe-base:latest jevision
      macos-tahoe-base is macOS 26. Its user is admin with the password admin; it logs in on its own and allows SSH. Change the password if others can reach the virtual machine over the network.
    3. Give it more memory and a bigger screen (optional; the virtual machine must be stopped): 
      tart set jevision --memory 8192 --cpu 4 --display 1920x1200
    4. Start it. A window opens with the virtual Mac's screen: 
      tart run jevision

    To share a folder of your Mac, such as your test project, start it with tart run jevision --dir=project:$HOME/my-tests. Inside, the folder appears as /Volumes/My Shared Files/project.

    Make a virtual machine with UTM

    UTM is a free app with windows and buttons instead of commands.

    1. Install UTM from mac.getutm.app and open it.
    2. Click Create a New Virtual Machine, then Virtualize, then macOS 12+.
    3. Leave the macOS installer file empty: UTM downloads the newest macOS that your Mac can run. Click Continue.
    4. Choose at least 8 GB of memory, 4 cores and 100 GB of disk, then Save.
    5. Start the virtual machine with the ▶ button. macOS installs itself, then shows the same setup assistant as a new Mac. Create a user and finish the setup.

    To share a folder of your Mac, choose it under Shared Directory in the virtual machine's window. Inside, it appears in /Volumes/My Shared Files.

    Install JEVision inside

    The simplest way is to copy the app you built on your Mac. In Terminal on your Mac, with the virtual machine running:

    scp -r apps/macos/build/JEVision.app admin@address:/Applications/

    Here admin is the user inside and address is the virtual machine's network address: tart ip jevision prints it; in UTM, open System Settings → Network inside. For scp and ssh to work in a UTM virtual machine, turn on System Settings → General → Sharing → Remote Login inside it first. You can also build JEVision inside, as in Getting started.

    Then, inside the virtual machine, open JEVision from Applications and choose JEVision → Install Command Line Tool… to get the jevision command. See Install the command-line tool.

    Install the app you are testing inside too, from its .app, .dmg or .pkg file.

    Allow permissions inside

    A virtual machine is a separate Mac, so it needs its own permissions. The ones you gave JEVision on your own Mac don't count inside. In the virtual machine's window, open System Settings → Privacy & Security and turn on the program that runs the tests in both lists:

    • Screen & System Audio Recording, to take screenshots;
    • Accessibility (Device Control and Data Access from macOS 27), to click and type.

    Which program that is depends on how you start tests:

    You start testsTurn on
    In the JEVision appJEVision. The app asks for both when it needs them.
    With jevision run in Terminal insideTerminal
    Over SSH from your Macsshd-session (sshd-keygen-wrapper on older macOS). It isn't in the list by itself: click +, press ⌘⇧G, type /usr/libexec/sshd-session and click Open.
    From a CI runnerThe runner's program, as named by the first run.

    Not sure? Run jevision run the way you will run it for real. If something is missing, it names the program and the lists to turn it on in, and exits without clicking anything.

    Allowing sshd-session lets every command started over SSH see the screen and control the virtual machine. Do it only in a virtual machine used just for testing, never on your own Mac.

    With Tart, do this once in a virtual machine you keep as a template, then start every run from a copy of it (see CI). Copies keep the permissions.

    Keep it ready for runs nobody watches

    Tests need a logged-in user and an unlocked screen, also in a virtual machine. For schedules, SSH and CI, set it up so it never waits for a person. Inside the virtual machine:

    1. Log in automatically. In System Settings → Users & Groups, set Automatically log in as to the test user. If the menu is dimmed, turn off FileVault in Privacy & Security first. Tart's ready-made virtual machines already log in by themselves.
    2. Never lock the screen. In System Settings → Lock Screen, set Start Screen Saver when inactive and Turn display off when inactive to Never, and Require password after screen saver begins or display is turned off to Never.
    3. Never sleep. In Terminal inside, run sudo pmset -a sleep 0 displaysleep 0.
    4. Secrets. If tests read secrets from the Keychain, run each test once inside and choose Always Allow when macOS asks. Over SSH and in CI it's easier to pass them as environment variables, as in Running in CI.

    JEVision keeps the display awake while a test runs, and never types into a locked screen: a run that finds the screen locked stops, and a scheduled run is skipped and marked “Skipped: the screen was locked”.

    Display size and Retina

    A virtual machine's screen is often a standard display, with one pixel per point, while a MacBook or an iMac has a Retina display with two. The same window is then twice as large in pixels on a Retina display, and text is drawn a little differently.

    • Clicks and found pictures work on either. JEVision clicks in points, not pixels, and looks for a picture at both densities, so a button saved on a Retina Mac is found in a standard-display virtual machine and the other way round.
    • Checks compare across densities by scaling the larger picture down. But text and thin lines don't match pixel for pixel, so an exact check, or a similar one with a high threshold, can fail. When it does, the failure says that the reference was saved on a display with a different pixel density.

    The fix is to save references on the kind of display the tests run on:

    • Save references in the virtual machine where the tests run. This is the most reliable way.
    • Or give the virtual machine a Retina display like your Mac's. In UTM, open the virtual machine's settings, choose Display and turn on HiDPI (Retina). Then check in System Settings → Displays inside that the resolution looks like your Mac's.
    • Or compare by meaning for screens with a lot of text.

    Keep the virtual machine's screen size the same from run to run. Positions in tests are relative to the app's window, so a different screen size matters only when the window itself changes size.

    Run tests from your Mac over SSH

    You can start tests in the virtual machine from Terminal on your Mac, without opening its window. This works when, inside the virtual machine, the test user is logged in (automatic login), the screen is unlocked and sshd-session has its permissions. Log in over SSH as that same user.

    ssh admin@address /usr/local/bin/jevision run my-tests --junit junit.xml --html reports

    The command runs in the user's home folder inside, so my-tests here is ~/my-tests there. Write the full path /usr/local/bin/jevision (or ~/.local/bin/jevision if you installed it just for yourself): a command given to ssh doesn't search the folders Terminal does. The exit status of jevision run comes back through ssh, so a script can tell whether the tests passed. See jevision run.

    To get the reports to your Mac, copy them:

    mkdir vm-results
scp -r admin@address:junit.xml admin@address:reports vm-results/

    Open the files in vm-results/reports in a browser. Each HTML report is a single file with its screenshots inside. The full runs, with the video, stay inside in the project's .jevision/runs folder. With a shared folder, run the project from /Volumes/My Shared Files and the reports appear on your Mac directly.

    CI on a virtual machine

    There are two ways to run tests in a virtual machine for CI.

    A runner inside the virtual machine

    Set the virtual machine up as in Keep it ready, then install a GitHub Actions self-hosted runner inside it, logged in as the test user, and install the runner as a service with ./svc.sh install. The workflow is the same as on a real Mac: see Running in CI. Allow Screen Recording and Accessibility for the program the first run names.

    A fresh virtual machine for every run

    For a clean Mac every time, keep the virtual machine you prepared as a template and run each job in a copy. A job on your Mac, for example on a runner installed there, can do it with Tart:

    tart clone jevision run-$GITHUB_RUN_ID
tart run --no-graphics run-$GITHUB_RUN_ID &
address=$(tart ip --wait 120 run-$GITHUB_RUN_ID)
scp -r -o StrictHostKeyChecking=no my-tests admin@$address:
ssh admin@$address /usr/local/bin/jevision run my-tests --junit junit.xml --html reports
status=$?
scp -r admin@$address:junit.xml admin@$address:reports .
tart stop run-$GITHUB_RUN_ID
tart delete run-$GITHUB_RUN_ID
exit $status

    Here my-tests is the project folder in the job's checkout. Install the app you test in the template, so every copy has it. --no-graphics only hides the window: the virtual machine still has its screen, and tests see it. To sign in over SSH without a password, add your Mac's SSH key to ~/.ssh/authorized_keys inside the template.

    How a report shows the virtual machine

    Every report records where the run ran. The report's header in the app and the HTML report show the computer, “Virtual machine” or “Physical Mac”, and the display, such as “Retina display (2×)” or “Standard display (1×)”. In report.json they are virtualMachine and displayScale. When a check fails in a virtual machine but passes on your Mac, look at the display first. See The report of a run.

    Limits

    • Two at a time. macOS lets one Mac run at most two macOS virtual machines at the same time.
    • Apple Account. Signing in to an Apple Account inside, for the App Store or iCloud, works only when both your Mac and the virtual machine run macOS 15 or later, and with some tools not at all. Install the app you test from its file instead of the App Store.
    • No camera and no microphone unless the tool passes them through. Tests of features that need them can't pass inside.
    • Graphics. A virtual machine has a simpler graphics processor than a real Mac. Most apps look the same, but heavy 3D, games and some video features may draw differently or not at all.
    • Speed. Apps start and draw a little slower. If a waitFor sometimes times out inside but never on your Mac, give it a few more seconds.
