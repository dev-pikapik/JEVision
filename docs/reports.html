    Run video and reports

    Every run leaves a record: a screenshot of each step, a video of the app if you want one, and reports to share or feed to CI.

    On this page

    • The report of a run

    The report of a run

    When a run ends, open its report from the result bar, the run history or the block that failed. A report shows:

    • the verdict and, when the test failed, the reason in one sentence, such as which picture didn't appear within how many seconds;
    • every step, with screenshots of the window before and after it;
    • for a check, the screen, the reference, their differences (differing pixels in red, left-out parts tinted) or one over the other, and how similar they were;
    • for a check by meaning, the AI provider, the model and its explanation;
    • the environment, the data row and, after retries, a sentence on what the retries tell you;
    • the video, if one was recorded, with a mark for each step.

    When the app changed on purpose, accept the run's screenshot as the new reference right from the report. See Checks and references.

    On the canvas, every block shows how it did in the last run, and a failed block shows the reason in the inspector.

    Verdicts and step statuses

    A run is passed, failed or cancelled (stopped with Esc twice, Ctrl-C or Stop). Each step is:

    • passed;
    • failed, the step where the test stopped;
    • Reference saved, when a check had no picture yet and saved the screen as its reference;
    • cancelled, when the run was stopped during the step.

    Run video

    JEVision can record a video of the app under test during a run. The video shows only the app under test, not the rest of the screen, and the report marks the moment of each step on it.

    SettingWhereChoices
    Record videoSettings → AdvancedNever, Only when a test fails (default), Always
    Keep run videos forSettings → Advanced7, 30 (default) or 90 days, or Forever
    --videojevision runoff, on-failure, always; default: the app's setting
    videoA scheduleoff, on-failure, always; default: the app's setting

    With “only when a test fails”, the video is recorded during every run and kept only if the test failed. Videos older than the chosen number of days are deleted after the next run. The video is saved as video.mp4 in the run's folder.

    HTML reports

    An HTML report is one file with every screenshot inside it, easy to attach to an issue or send to someone without JEVision. The run's video, too large to put inside, is copied next to the file under the same name ending in .mp4.

    • In the app: export the report from the report window.
    • On the command line: jevision run tests/ --html reports saves the HTML report of every run in the reports folder.

    JUnit XML

    JUnit XML is the format CI systems such as GitHub Actions, GitLab and Jenkins read to show test results. jevision run tests/ --junit junit.xml saves one file for all the tests of the run.

    • Each test is a test case. In a data-driven test, each row is a test case of its own, such as Sign in [Row 2: Bo].
    • A failure of a test in quarantine is listed as skipped, with the reason and the failure.

    Where runs are saved

    Every run is saved in the project's .jevision/runs folder, in a folder named after the time and the test, such as .jevision/runs/20261018-031500-sign-in. It holds:

    • report.json, the report in a form programs can read;
    • the screenshots of the steps;
    • video.mp4, when a video was kept;
    • copies of the files that openFile blocks opened.

    The .jevision folder holds results, not tests, so keep it out of git. After the first run in a git project, JEVision offers to add it to .gitignore.

    What reports never contain

    • Secret values. They are masked wherever they would appear.
    • Hidden areas. Parts of the window listed in a reference's hide are covered in every screenshot before it is saved. See Checks and references.
    • API keys of AI providers.
