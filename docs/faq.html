    Permissions

    JEVision tests apps the way a person uses them: it looks at the screen and uses the mouse and keyboard. macOS allows that only with two permissions, which you give once in System Settings → Privacy & Security:

    List in System SettingsWhy JEVision needs it
    Screen & System Audio Recording (called Screen Recording in older macOS)To see the app under test: to find what to click, wait for screens and compare them with references.
    Accessibility (called Device Control and Data Access from macOS 27)To click, type and press keys, and to read the names of buttons while recording.

    Which app gets them. macOS gives permissions to apps, not commands:

    • For the JEVision app, turn on JEVision. The app shows each permission as Allowed or Not allowed, and its Allow button opens the right list in System Settings. It notices the change within seconds, without a restart.
    • For jevision on the command line, turn on the app it runs in: Terminal, iTerm, your editor, or your CI agent. jevision run names that app when a permission is missing.

    It is turned on, but still doesn't work.

    • Quit and reopen the app the permission is for. macOS often offers to do this; accept it.
    • If the app isn't in the list, click + under the list and choose it.
    • After an update or a rebuild from source, macOS may still remember the older copy of JEVision, so its switch does nothing. JEVision notices this and shows Reset and Allow next to the permission: it makes macOS forget the old entry (tccutil reset, for JEVision only) and opens the list again, where you turn JEVision on.

    “jevision can't run tests”

    jevision run checks the Mac before it starts, and says what is in the way:

    “there is no logged-in user with a screen”
    Tests need a screen, so they run only in the session of a user logged in at the Mac: from Terminal, from a CI agent started in that session, or over SSH as that same user while they stay logged in at the screen (see Virtual machines). They can't run as a system service.
    “the screen of this Mac is locked”
    Unlock it and run again. For runs nobody watches, turn off the automatic lock in System Settings → Lock Screen. JEVision never types into a locked screen, where a password field would get the input.
    “macOS hasn't allowed … to record the screen and control the computer”
    See Permissions; the message lists the steps.

    The run paused or stopped

    • The run paused when I moved the mouse. That's on purpose: when you touch the mouse or keyboard, JEVision steps aside so you and the test don't fight over the pointer. The run panel says “Paused — you moved the mouse”. Click Resume when your hands are off. A run started with jevision run goes on by itself once the mouse and keyboard rest for 3 seconds. To turn this off, clear Pause when you move the mouse in Settings → General → While a test runs.
    • How do I stop a run? Press Esc twice, from any app, unless Stop with Esc Esc is turned off in the same place. On the command line, Ctrl-C works too. The test is reported as stopped.
    • Can I use the Mac during a run? Not really: the test needs the mouse, the keyboard and the app's window in front. Run tests on a separate Mac or a separate user account, or at times you don't need it, such as with schedules.

    A picture wasn't found

    A click target or a waitFor looks for a picture in the app's window. When it isn't found:

    • The app was slower than usual. Put a waitFor before the step, or give it a longer timeout.
    • The app looks different now: another size, theme, language or version. Open the report, compare what the step was looking for with the screenshot, and take a new picture of the target.
    • Something covered the window, such as a notification or another window. Turn on Do Not Disturb (a Focus) while tests run.

    A check fails though the screen looks right

    Open the report and look at the differences in red. Usually it's one of these:

    • Parts that change on their own: a clock, a date, a counter, an animation, a blinking cursor. Add them to the reference's ignore areas, or check a smaller area. See Areas.
    • A real change you wanted. Accept the new screen as the reference. See Accepting changes.
    • A reference from a display of another density, such as a Retina Mac, compared in a virtual machine with a standard display. The failure says so. See Display size and Retina.
    • Slightly different drawing on another Mac or display. Lower the threshold a little, or check by meaning instead.

    When a test sometimes passes and sometimes fails, see Retries, flaky tests and quarantine.

    Tests fail in dark mode

    A screen in dark appearance doesn't look like a reference taken in light appearance. JEVision keeps a second reference for dark appearance, such as refs/inbox.dark.png, and makes it the first time a check runs in dark mode; the report marks that step New reference saved, so look at it once. See Dark appearance.

    macOS asks about the Keychain

    The first time jevision reads a secret from the Keychain, macOS asks whether to allow it. Choose Always Allow, especially for schedules and CI, where nobody is there to answer. In CI, you can pass secrets as environment variables instead. See Where a secret's value comes from.

    “The file uses format 2 from a newer JEVision”

    The file was saved by a newer version of JEVision. Update JEVision on this Mac. JEVision won't open such a file, so it can't damage it. See Format versions.

    Updating JEVision

    JEVision looks for a new version when it opens and once a day, and asks before installing it: Install Update, Remind Me Later or Skip This Version. The window shows what's new in English or in Russian, after the language of your Mac. To look right away, choose JEVision ▸ Check for Updates….

    In Settings ▸ Updates you see which version you have and when JEVision last looked, and you can:

    • turn off Check for updates automatically;
    • turn on Download and install updates automatically: JEVision downloads an update in the background and installs it when you quit;
    • turn on Get beta versions to try new features before the release. A beta can have bugs. When you turn it off, you keep the beta until the next release replaces it.

    JEVision installs only updates signed by the JEVision project, and never an older version than the one you have.

    When an update stores tests or settings in a new way, JEVision first saves a copy of them in ~/Library/Application Support/JEVision/Backups, in a folder named after the version and the date, so an older JEVision can still open them. If the copy can't be made, the update isn't installed and JEVision says why. JEVision never deletes these copies; Settings ▸ Updates ▸ Show in Finder opens the folder, and you can delete the ones you don't need.

    Installed with Homebrew? The built-in updates work the same way, and the cask knows it (auto_updates true), so a plain brew upgrade leaves JEVision alone. To update with Homebrew instead, name it: brew upgrade --cask jevision. brew uninstall --zap --cask jevision also removes the copies.

    What to commit

    Commit the tests, their images and CSV files, and the jevision.*.json files. Leave out the .jevision folder: it holds run results and history for one Mac. After the first run in a git project, JEVision offers to add it to .gitignore. See Files in a project.

    Logs and crash reports

    JEVision writes a log on your Mac, in ~/Library/Logs/JEVision: the project opened, a run started and how it ended, and what went wrong. Open the folder with Settings → Advanced → Logs → Show in Finder, and attach JEVision.log to a bug report if it helps. Log detail chooses Errors only, Normal (the default) or Detailed, which adds every step of a run. The log keeps about 2 MB: when JEVision.log is full, it becomes JEVision.1.log, and only the newest four files are kept. It never holds typed text or secrets, and anything that looks like a key, a token or a password is hidden.

    If JEVision crashes, it can keep the report on your Mac. Turn on Settings → Advanced → Save crash reports. The next time JEVision starts, macOS hands it the report (up to a day later), and JEVision keeps the last 20 in ~/Library/Application Support/JEVision/Crash Reports. Nothing is sent anywhere. To include one in a bug report, choose Add a Crash Report in the bug report window: its summary goes into the description, where you can read and change it before sending.

    Questions about testing

    Which apps can I test?
    Any app on your Mac with a window: your own, someone else's, native or built with web technology. JEVision doesn't need the app's code or any changes to it.
    Do I need to know how to code?
    No. Record a test by using the app, and edit it on the canvas. The JSON file is there for those who want it.
    Do tests send my screen anywhere?
    Only checks by meaning send a screenshot to the AI model you choose, and you can choose a model that runs on your Mac. Every other check compares pictures on your Mac. Two things you turn on yourself also send a picture: email notifications show the screenshot of the failed step, and a bug report you file on GitHub includes the screenshots you choose. Private areas are painted over in both.
    Does it test iPhone apps or websites?
    JEVision tests Mac apps. A website can be tested in a Mac browser like any other app. The iPhone app is a remote for running tests on your Mac, not a way to test iPhone apps.
