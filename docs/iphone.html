    iPhone remote

    JEVision Remote turns an iPhone into a remote for JEVision on your Mac: look through tests, start a run, follow it block by block and read why a test failed, from anywhere.

    On this page

    • What you can do
    • Get the app
    • Pair an iPhone
    • Settings on the Mac
    • Reaching the Mac from anywhere
    • Versions and updates
    • Privacy and security

    What you can do

    • Browse the projects and tests on each paired Mac.
    • See a test drawn as its flow, with its last results, and read its card: description, type, priority, status and author.
    • Read the sticky notes on a test's canvas: their Markdown text, who wrote them, the replies, links and the names of attached files. Tap a note to open it whole, and hide the resolved ones. Notes are read-only on the iPhone; attached files stay on the Mac.
    • Run a test, or just one row of its data table, if the Mac allows it, and follow it block by block, or stop it. A run that waits for another run to give up the Mac's screen shows a clock and says who has it.
    • Read reports with a one-phrase reason for each failure, and open screenshots only when you need them.
    • Look through a project's run history.

    No Mac at hand? Tap See an Example on the first screen to look around a Mac built into the app, with tests, notes and runs. The example uses no network and saves nothing.

    Tests, pictures and secrets stay on the Mac. The iPhone asks for what you open and keeps nothing but the list of paired Macs.

    Get the app

    JEVision Remote isn't in the App Store yet, so you build it from the source code with Xcode. You need:

    • Xcode 26 or later, and Rust, installed with rustup;
    • an iPhone with iOS 26 or later and a passcode;
    • an Apple ID or developer team to sign the app.
    1. Open apps/ios/JEVisionRemote.xcodeproj in Xcode.
    2. In the JEVisionRemote target, open Signing & Capabilities and choose your team. With your own Apple ID, also change the bundle identifier to one you own.
    3. Connect the iPhone, select it as the run destination and press Run.

    The first build also builds the JEVision core, so it takes a few minutes. apps/ios/README.md in the repository explains building for the Simulator.

    Pair an iPhone

    1. On the Mac, open JEVision → Settings → iPhone & Remote and turn on Allow remote access.
    2. Choose what the next device can do: Can run tests or View only.
    3. On the iPhone, open JEVision Remote and tap Pair a Mac.
    4. Point the camera at the pairing code on the Mac and confirm with Face ID or the passcode.

    A pairing code works once and expires in five minutes. To pair another device, click Show a Code for Another Device.

    Settings on the Mac

    Allow remote access
    Paired iPhones can reach this Mac only while it is on.
    Ask on this Mac before a remote run
    A run started from an iPhone waits until someone at the Mac allows it.
    Keep this Mac awake while remote access is on
    The Mac won't fall asleep on its own, so it can be reached at any time.
    Activity log
    Who ran what, and when: pairings, connections and remote runs.
    Devices
    Each paired iPhone, and each assistant on another computer, what it can do and when it last connected. Disconnect cuts it off at once; to use it again, pair it with a new code.
    Relay
    Standard, My own (the address of a relay you run) or None. See below.

    Reaching the Mac from anywhere

    The iPhone connects to the Mac directly when it can, for example on the same Wi-Fi; the first time, iOS asks to allow access to the local network. When a direct connection isn't possible, a relay forwards the traffic. The relay carries only encrypted data it can't read. With the relay set to None, the iPhone reaches the Mac only on the same Wi-Fi or over a VPN.

    No ports are opened on the Mac, and you don't need to set up your router.

    Versions and updates

    The iPhone app and JEVision on the Mac don't have to be the same version. When they connect, each says which versions of the remote protocol it speaks, and the Mac picks the newest one both know. An iPhone app a little older or newer than the Mac keeps working.

    When there is no version both know, the connection doesn't just fail: the iPhone says which side to update and to which version, either the iPhone app or JEVision on the Mac, and the Mac's activity log says the same under the device's name. A pairing code from a newer JEVision asks you to update the iPhone app instead of calling the code invalid.

    How long older versions keep working:

    • JEVision on the Mac works with iPhone apps released in the last 12 months.
    • Anything removed from the protocol is first marked as going away for at least six months and at least one release.
    • A request the Mac doesn't know yet is answered “not supported by this Mac”, and the connection stays open, so a newer iPhone app can still do everything the Mac does support.

    The list of paired Macs on the iPhone and the list of devices on the Mac keep whatever a newer version added to them. A list saved by a newer version in a way this one can't change is read but never overwritten, and you are asked to update instead. A list that can't be read at all is set aside as a copy next to it, so nothing is lost, and you are asked to pair again.

    For developers: the connection's ALPN names its purpose, jevision/phone/1 for the iPhone and jevision/assistant/1 for assistants on another computer, and doesn't change with versions. The version is agreed in the first message instead: the device sends the range of protocol versions it speaks and its app version, and the Mac answers with the version chosen and its own app version. Protocol 1 is the first. New fields are added so that older versions can skip them, and a request, answer or error code an older version doesn't know reads as unknown there instead of breaking the connection.

    Privacy and security

    • End-to-end encryption. Every request goes over an encrypted connection between the iPhone and the Mac, directly or through a relay that can't read it.
    • A key that can't be copied. The iPhone makes its own key in the Secure Enclave the first time it is used. The key never leaves the iPhone, needs you present to use it and isn't backed up. The Mac knows the iPhone only by the public half of that key.
    • App lock. The app asks for Face ID or the passcode when opened, after a chosen time in the background (immediately, or after 1, 5 or 15 minutes) and at least every 8 hours. Locking drops every connection, and the app switcher shows the app covered.
    • The Mac decides. It chooses whether an iPhone may only view or also run tests, and can disconnect it at any time. Secrets and API keys are never sent to the phone.
    • Little stored. The iPhone saves only the list of paired Macs: name, identity and addresses, in a file protected by iOS data protection. Forgetting a Mac on the iPhone removes it from that list; to also cut the iPhone off, disconnect it on the Mac.

    The privacy policy says what the app stores, what it sends and to whom.
